# 首页概览 `/dashboard` 设计

## 1. 目标与结论

### 1.1 目标
- 新增首页概览页面 `/dashboard`，作为登录后的默认进入页。
- 基于 `ui/dashboard.pen` 落地桌面端概览页面，展示我的任务执行总览。
- 接入真实数据，不使用 Mock 占位。
- 复用现有任务详情抽屉能力，保证首页与敏捷面板的任务预览体验一致。

### 1.2 已确认结论
- 新页面路径为 `/dashboard`，不是替换现有 `/`。
- 登录成功后默认跳转到 `/dashboard`。
- 页面数据通过后端新增聚合接口统一提供，不采用前端多接口拼装。
- KPI 卡片用于导流到 `/my-todo`。
- 概览页中的列表项点击后打开任务详情抽屉，复用现有详情组件能力。
- 不做移动端适配，仅覆盖当前后台桌面端使用场景。

## 2. 范围与非目标

### 2.1 本次范围
- 前端新增 `/dashboard` 路由页面与页面私有子组件。
- 登录默认回跳逻辑调整为默认进入 `/dashboard`。
- 左侧菜单新增“首页概览”入口。
- 后端新增首页概览聚合查询接口。
- 抽离任务详情抽屉为共享能力，供概览页与敏捷面板共同复用。
- 为新增接口、页面交互与关键状态补充必要单元测试。

### 2.2 非目标
- 不替换现有 `/` 路由内容。
- 不新增图表、拖拽、筛选面板、自定义布局等扩展能力。
- 不做移动端布局适配。
- 不改造任务详情抽屉的核心交互模型，只做共享抽离。
- 不在本次引入新的外部依赖。

## 3. 现状摘要

### 3.1 当前前端现状
- 根路由 `/` 当前仍是占位内容，不具备实际业务承载能力。
- 登录页当前默认回跳到 `/`，除非 URL 显式传入 `redirect`。
- 待办页面 `/my-todo` 已具备列表查询能力，但当前筛选参数只覆盖标题、优先级与状态。
- 敏捷面板已经存在任务详情抽屉 `TaskPreviewDrawer` 与抽屉打开服务 `openTaskPreviewDrawer`，但实现挂在敏捷面板私有目录下，首页不能直接长期依赖该私有路径。

### 3.2 当前后端现状
- 后端已有 `/project/task/my-todo` 用于返回我的待办分页列表。
- 后端已有任务详情、任务编辑、子任务、任务变更日志等基础能力。
- 当前不存在统一返回首页概览统计、今日待办、本周待办、逾期风险的聚合接口。

### 3.3 当前痛点
- 首页没有实际信息承载，登录后的首屏价值较低。
- 如果前端直接拼装现有接口，今日、本周、逾期风险的口径会分散在前后端两侧，后续维护成本高。
- 任务详情抽屉目前耦合在敏捷面板目录中，难以被其他页面稳态复用。

## 4. 方案对比与最终选择

| 方案 | 做法 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- | --- |
| A | 后端新增首页概览聚合接口，前端单页消费 | 请求少、口径统一、最贴设计稿、便于后续扩展 | 需要补后端查询与 VO | 采用 |
| B | 前端并发调用多个现有接口，自行统计与分组 | 后端改动较少 | 统计与筛选逻辑分散，边界复杂，容易漂移 | 不采用 |
| C | 新增统计接口，列表复用现有 `my-todo` | 改动量居中 | 仍存在前后端职责割裂，后续演进易继续分叉 | 不采用 |

### 4.1 最终方案
- 采用方案 A。
- 后端新增首页概览接口，一次性返回 KPI 汇总、今日待办、本周待办、逾期风险三类列表。
- 前端新增 `/dashboard` 页面，按 `dashboard.pen` 的信息结构组织页面。
- 任务详情抽屉从敏捷面板私有目录中抽为共享能力，首页列表项点击直接复用。

## 5. 页面与交互设计

### 5.1 页面结构
- 顶部标题区：
  - 主标题：`我的概览`
  - 副标题：围绕我的任务、今日待办、本周待办与逾期风险的执行面板
- 第一行 KPI 卡片：
  - 我的任务
  - 今日待办
  - 本周待办
  - 已完成任务数
- 主体双栏区域：
  - 左侧：
    - 今日待办列表
    - 本周待办列表
  - 右侧：
    - 逾期风险列表

### 5.2 视觉落地原则
- 信息结构与层级遵循 `ui/dashboard.pen`。
- 落地时沿用项目现有 Ant Design 与布局体系，不追求逐像素复制设计稿。
- 保留设计稿中的浅色背景、分卡片层次与风险色语义，但控制在现有后台风格内。

### 5.3 点击行为
- KPI 卡片点击后跳转 `/my-todo`：
  - `我的任务`：跳转到 `/my-todo`
  - `今日待办`：跳转到 `/my-todo` 并带今日筛选参数
  - `本周待办`：跳转到 `/my-todo` 并带本周筛选参数
  - `已完成任务数`：跳转到 `/my-todo` 并带 `status=done`
- 今日待办、本周待办、逾期风险中的列表项：
  - 点击后打开任务详情抽屉
  - 不直接跳项目任务页

### 5.4 任务详情抽屉复用策略
- 复用现有 `TaskPreviewDrawer` 的展示与交互能力：
  - 概览
  - 子任务
  - 变更日志
  - 状态切换
  - 编辑入口
- 不让 `/dashboard` 直接依赖 `agile-board` 私有目录。
- 将抽屉组件移动到共享组件目录，将打开服务移动到共享 service 目录。
- 建议的新归属为：
  - `admin-rsbuild/src/components/business/TaskPreviewDrawer/`
  - `admin-rsbuild/src/service/taskPreviewDrawerService.tsx`
- 敏捷面板与 `/dashboard` 共同依赖新的共享能力，避免重复实现。

## 6. 数据接口设计

### 6.1 新增接口
- 路径：`GET /project/task/dashboard`
- 目标：一次性返回首页概览所需全部数据
- 风格：保持现有项目接口风格，增加 Swagger 注解与响应结构说明

### 6.2 返回结构

```ts
interface DashboardOverviewResponse {
  summary: {
    myTaskCount: number;
    todayTodoCount: number;
    weekTodoCount: number;
    doneTaskCount: number;
  };
  todayTodos: DashboardTaskItem[];
  weekTodos: DashboardTaskItem[];
  overdueRisks: DashboardRiskItem[];
}

interface DashboardTaskItem {
  id: number;
  projectId: number;
  projectName?: string;
  projectCode?: string;
  title: string;
  priority: 'high' | 'medium' | 'low';
  status: string;
  dueTime?: string;
  startTime?: string;
  workDays?: number;
  assignee?: string;
}

interface DashboardRiskItem {
  id: number;
  projectId: number;
  projectName?: string;
  title: string;
  priority: 'high' | 'medium' | 'low';
  dueTime?: string;
  overdueDays: number;
  riskLevel: 'high' | 'medium';
}
```

### 6.3 设计原则
- 页面统计与列表口径统一在后端收敛，前端不再自行计算核心业务统计。
- 列表项字段尽量复用现有任务详情与任务卡片常用字段，减少前端类型碎片化。
- 风险列表只补充首页特有的 `overdueDays` 与 `riskLevel`。

## 7. 统计与筛选口径

### 7.1 KPI 口径
- `myTaskCount`
  - 当前用户作为负责人、且任务未删除的任务总数。
  - 不限制完成状态。
- `todayTodoCount`
  - 当前用户作为负责人。
  - `dueTime` 落在今天。
  - 状态不为已完成、不为已取消。
- `weekTodoCount`
  - 当前用户作为负责人。
  - `dueTime` 落在当前自然周。
  - 状态不为已完成、不为已取消。
- `doneTaskCount`
  - 当前用户作为负责人。
  - 状态为已完成。

### 7.2 列表口径
- `todayTodos`
  - 今日截止且未完成未取消的任务。
  - 排序：优先级高到低，再按截止时间近到远。
- `weekTodos`
  - 本周截止且未完成未取消的任务。
  - 为避免首页重复感，排除已出现在 `todayTodos` 中的任务。
  - 排序：优先级高到低，再按截止时间近到远。
- `overdueRisks`
  - `dueTime` 早于当前时间，且未完成未取消的任务。
  - 排序：逾期天数倒序，再按优先级高到低。

### 7.3 多租户约束
- 查询必须基于当前登录上下文中的 `tenantId` 做数据隔离。
- 任何聚合统计与列表明细都不能跨租户聚合。

## 8. 前端实现设计

### 8.1 路由设计
- 新增文件路由：`admin-rsbuild/src/routes/dashboard/index.tsx`
- 保持 `/` 不变。
- 通过 `createFileRoute('/dashboard/')` 注册新页面。

### 8.2 页面拆分建议
- 页面入口负责：
  - 发起查询
  - 组织数据
  - 管理任务详情抽屉打开行为
  - 触发刷新
- 页面私有组件负责：
  - KPI 行
  - 今日待办卡片
  - 本周待办卡片
  - 逾期风险卡片
- 拆分原则：
  - 单文件尽量控制在 400 行内
  - 页面私有子组件继续使用 `#` 前缀命名

### 8.3 API 层
- 新增前端 API 模块：
  - `admin-rsbuild/src/api/modules/dashboard.ts`
  - `admin-rsbuild/src/api/modules/dashboard.types.ts`
- 查询优先使用 TanStack Query。
- 页面刷新与抽屉更新后，通过查询失效机制刷新概览数据。

### 8.4 与任务抽屉、任务编辑的协作
- `/dashboard` 页面打开任务抽屉时需要传入：
  - 任务 ID
  - 状态配置列表
  - 刷新回调
  - 编辑回调
- 编辑回调继续复用现有 `openTaskModal`。
- 抽屉内状态变更或编辑成功后：
  - 刷新首页概览查询
  - 失效待办列表与任务列表相关缓存，保持跨页面一致性

### 8.5 `/my-todo` 跳转筛选补充
- 由于当前 `/my-todo` 不支持 today/week 维度筛选，需补充轻量筛选参数。
- 建议新增查询参数：
  - `range=today`
  - `range=week`
- 首页 KPI 点击跳转时统一携带该参数。
- `/my-todo` 页面内部根据 `range` 生成对应查询条件。

## 9. 登录与菜单设计

### 9.1 登录默认跳转
- 登录页当前默认 `redirect` 为 `/`。
- 调整为默认 `redirect=/dashboard`。
- 如果登录地址已经显式传入 `redirect`，则仍优先使用用户显式目标。

### 9.2 菜单入口
- 左侧菜单新增“首页概览”。
- 菜单高亮路径为 `/dashboard`。
- 当前菜单来源于登录权限接口返回的 `permission.menus`。
- 需要同步补充后端菜单配置数据，确保“首页概览”进入当前用户可见菜单树。

## 10. 后端实现设计

### 10.1 控制器与服务
- 在项目任务控制器中新增首页概览查询接口。
- 新增对应的查询服务，用于封装首页概览统计与列表查询逻辑。
- 避免将首页概览的聚合逻辑散落在现有待办列表服务中。

### 10.2 查询策略
- 统计与列表查询在服务层统一收口。
- 优先复用已有任务读模型与基础 Mapper 条件拼装能力。
- 对于 today/week/overdue 条件，统一由后端判断时间边界，避免前端时间口径漂移。

### 10.3 Swagger 与响应对象
- 新增首页概览响应 VO、列表项 VO、风险项 VO。
- 所有新增接口与字段都补充 Swagger 注解。
- 文档描述中明确 today/week/overdue 的业务含义。

## 11. 空态、错误态与加载态设计

### 11.1 加载态
- 页面首次加载时：
  - KPI 使用骨架占位
  - 三块列表卡片使用骨架占位
- 避免出现整页闪烁或布局跳变。

### 11.2 错误态
- 概览接口失败时：
  - 页面主体显示错误提示
  - 提供重试入口
  - 不直接白屏
- 任务详情抽屉失败时：
  - 沿用现有 `TaskPreviewDrawer` 的失败提示样式与行为

### 11.3 空态
- 今日待办为空：
  - 卡片显示轻量空态文案
- 本周待办为空：
  - 卡片显示“本周暂无待办”
- 逾期风险为空：
  - 显示“当前无逾期风险”
  - 保留卡片容器，避免页面结构塌陷

## 12. 测试与验证方案

### 12.1 后端测试
- 首页概览接口能正确返回四个 KPI 统计。
- 今日、本周、逾期三类列表过滤条件正确。
- 已完成、已取消任务不会错误进入 today/week/overdue 列表。
- 多租户数据隔离生效，不会串租户。
- 响应字段与 Swagger 定义保持一致。

### 12.2 前端测试
- `/dashboard` 页面成功态、空态、错误态渲染正确。
- KPI 卡片点击能跳转到正确的 `/my-todo` 参数组合。
- 列表项点击能打开共享任务详情抽屉。
- 抽屉编辑或状态变更后，会触发 dashboard 查询刷新。
- 共享抽屉抽离后，敏捷面板原有行为不回归。

### 12.3 联调验证
- 登录后默认进入 `/dashboard`。
- 左侧菜单能进入并高亮 `/dashboard`。
- 概览数字与列表数据能和后端实际数据对应。
- 抽屉详情可正常查看、编辑、切换状态。
- 状态变更后首页 KPI 与列表同步更新。

## 13. 风险与控制策略

### 13.1 主要风险
- 共享抽屉从敏捷面板私有目录抽离时，可能影响现有敏捷面板行为。
- `/my-todo` 新增 `range` 查询能力后，若参数处理不统一，可能出现首页跳转后筛选失效。
- 后端若直接复用现有分页待办逻辑但未收口时间口径，容易让 today/week/overdue 结果与 KPI 不一致。

### 13.2 控制策略
- 抽屉共享时保持入参与行为不变，只调整目录归属与依赖位置。
- `range` 参数收敛为固定枚举，不做自由文本解析。
- 首页全部核心统计口径统一由概览接口提供，前端不自行二次运算。
- 为敏捷面板与 `/dashboard` 同时补充回归测试，防止共享能力抽离后功能回退。

## 14. 验收标准

1. 新增 `/dashboard` 页面，并按 `dashboard.pen` 的信息结构完成桌面端落地。
2. 登录成功后默认进入 `/dashboard`。
3. 左侧菜单可进入并高亮 `/dashboard`。
4. 页面通过真实接口返回 KPI、今日待办、本周待办、逾期风险数据。
5. KPI 卡片点击后跳转到 `/my-todo` 的对应筛选结果。
6. 页面列表项点击后打开任务详情抽屉，而不是跳项目任务页。
7. 任务详情抽屉复用现有详情组件能力，支持查看、编辑、状态切换。
8. 抽屉中的编辑或状态变更成功后，首页概览数据会刷新。
9. today/week/overdue 数据口径在前后端保持一致。
10. 新增能力补充必要单元测试，且不回归敏捷面板现有功能。
