# 敏捷看板任务卡片强调色与子任务空态收敛设计

## 1. 目标与结论

### 1.1 目标
- 修复 `/agile-board` 页面父任务卡片“背景色没有了”的视觉退化问题。
- 在不改动通用卡片默认语义的前提下，恢复敏捷看板场景特有的状态强调感。
- 去掉“无子任务”时的 `Empty` 空态提示，仅保留必要的信息结构。

### 1.2 已确认结论
- 父任务卡片不恢复整卡浅色背景，保持白底。
- 状态强调色不使用左侧色条、顶部色带等新增结构。
- 强调色采用“1px 半透明状态色边框 + 轻微染色阴影”的方式恢复，属于局部强调。
- 无子任务时保留“子任务列表”标题与 `已完成 0 / 0` 统计文案。
- 无子任务时不再展示 `Empty` 组件和“暂无子任务”说明。

## 2. 范围与非目标

### 2.1 本次范围
- `admin-rsbuild/src/routes/agile-board/components/BoardColumn.tsx`
- `admin-rsbuild/src/routes/agile-board/components/AgileBoardTaskCard.tsx`
- `admin-rsbuild/src/routes/agile-board/styles/task-card-shell.styled.tsx`
- `admin-rsbuild/src/routes/agile-board/#TaskSubtaskPanel.tsx`
- 与上述改动直接相关的前端单元测试

### 2.2 非目标
- 不改动后端接口、数据结构和状态列配色生成逻辑。
- 不把敏捷看板状态色能力默认注入通用 `TaskCard`，避免影响其他页面。
- 不新增新的任务卡片布局结构。
- 不调整子任务加载中、加载失败时的反馈形式。

## 3. 现状诊断

### 3.1 当前问题一：父任务卡片视觉反馈过弱
- 当前列容器 `ColumnSurface` 仍保留 `accentColor` 与列背景色。
- 但父任务卡片经 `AgileBoardTaskCard -> TaskCard` 这一层抽象后，卡片本体只保留白底、基础阴影和优先级标签。
- 结果是列级状态色与任务卡片之间的视觉关联被削弱，用户感知上像“原来的背景色没了”。

### 3.2 当前问题二：子任务为空时提示过重
- `#TaskSubtaskPanel.tsx` 在无子任务、非加载、非失败时，会直接渲染 `Empty description="暂无子任务"`。
- 对当前交互来说，用户已经有“快捷创建”入口，且列表标题与统计文案已经足够表达“当前没有子任务”。
- 继续显示 `Empty` 会让抽屉信息密度失衡，也与“轻量补充子任务”的使用场景不匹配。

## 4. 方案对比

### 4.1 方案 A：扩展通用 `TaskCard`，增加状态强调色能力
- 优点：未来其他页面如果也需要状态色，可以直接复用。
- 缺点：会把敏捷看板的场景语义塞进通用组件，扩大组件职责。
- 结论：不采用。

### 4.2 方案 B：在 `agile-board` 场景包装层恢复状态强调色
- 优点：改动范围小，只影响敏捷看板；符合“白底卡片 + 局部强调色”的已确认方向。
- 缺点：需要在场景层补一层颜色透传。
- 结论：采用。

### 4.3 方案 C：直接在列组件用选择器覆盖通用卡片内部样式
- 优点：实现速度快。
- 缺点：依赖内部 DOM 结构，后续 `TaskCard` 结构调整时容易失效。
- 结论：不采用。

## 5. 最终设计

### 5.1 设计原则
- 通用 `TaskCard` 只负责信息结构、通用交互和基础卡片样式。
- 敏捷看板特有的状态表达放在场景包装层，避免跨页面副作用。
- 强调色只做“轻度提示”，不抢占标题、优先级、子任务列表等核心信息的注意力。

### 5.2 父任务卡片强调色设计
- 颜色来源沿用当前列元数据 `AgileBoardColumnMeta.accentColor`。
- `BoardColumn` 在渲染每个父任务卡片时，把当前列的 `accentColor` 透传给 `AgileBoardTaskCard`。
- `AgileBoardTaskCard` 不修改通用 `TaskCard` 的内容模型，只把强调色交给看板壳层样式。
- `task-card-shell.styled.tsx` 负责组合看板场景外壳样式：
  - 默认态：维持白底，使用 `1px` 半透明状态色边框，并在现有阴影中混入轻微状态色。
  - 拖拽浮层态：保留现有浮层阴影层级，并让边框与染色阴影比默认态稍强。
  - 禁用态：不放大强调色，避免与“更新中不可操作”语义冲突。
  - 拖拽中的原卡片继续按现有 `opacity` 处理，不增加额外色彩变化。

### 5.3 子任务空态收敛设计
- `TaskPreviewSection title="子任务列表"` 保留。
- 统计文案 `已完成 {completedCount} / {totalCount}` 保留。
- 仅当存在子任务数据时，渲染子任务卡片列表。
- 当 `totalCount === 0` 且非加载、非失败时，不渲染任何额外占位内容。
- 加载态继续使用 `Skeleton`，失败态继续使用 `Alert`，避免误伤真实异常反馈。

## 6. 组件职责与数据流

### 6.1 `BoardColumn`
- 继续负责列级拖拽落点和列标题展示。
- 新增职责：把当前列的 `accentColor` 传给父任务卡片包装层。
- 不负责直接覆盖通用 `TaskCard` 内部样式。

### 6.2 `AgileBoardTaskCard`
- 继续负责 `dnd-kit` 的 `useDraggable` 接入。
- 继续负责把 `AgileBoardTask` 适配成通用卡片数据。
- 新增职责：接收并下发看板场景强调色。

### 6.3 `task-card-shell.styled.tsx`
- 负责看板卡片外层视觉语义，包括：
  - 宽度
  - 拖拽中透明度
  - 场景强调色边框/阴影
  - 浮层尺寸与浮层强调色
- 不承载卡片正文排版逻辑。

### 6.4 `TaskCard`
- 保持当前通用边界不变。
- 不新增看板专属字段，不直接感知列状态色。

### 6.5 `TaskSubtaskPanel`
- 保持快捷创建区和统计区不变。
- 去掉无子任务时的 `Empty` 分支渲染。

## 7. 测试与验证策略

### 7.1 组件验证
- 验证父任务卡片在敏捷看板场景下能接收到列强调色并生成对应外层样式。
- 验证拖拽浮层卡片仍能正常渲染，不丢失既有宽度和悬浮层级感。

### 7.2 子任务面板验证
- 无子任务时仍显示“子任务列表”标题。
- 无子任务时仍显示 `已完成 0 / 0`。
- 无子任务时不再出现“暂无子任务”。
- 加载中与失败时的反馈不回归。

### 7.3 回归验证
- 看板列拖拽换状态行为不受影响。
- 点击父任务卡片仍能打开详情抽屉。
- 优先级切换交互不受影响。

## 8. 实施顺序建议

1. 调整 `BoardColumn` 与 `AgileBoardTaskCard` 的场景色传递。
2. 在 `task-card-shell.styled.tsx` 增加强调色壳层样式。
3. 收敛 `TaskSubtaskPanel` 的无子任务分支。
4. 补充或更新对应测试。
5. 运行前端相关测试验证改动范围。

## 9. 验收标准

- `/agile-board` 父任务卡片保持白底，但重新具备可感知的状态强调色。
- 强调色实现为“半透明状态色边框 + 轻微染色阴影”，而不是整卡彩底、左色条或顶色带。
- 无子任务时，“子任务列表”标题与 `已完成 0 / 0` 正常显示。
- 无子任务时，不再出现 `Empty` 空态和“暂无子任务”文字。
- 既有拖拽、预览、优先级切换、加载失败反馈不回归。
