# 敏捷面板任务时长字段调整设计

## 1. 目标与结论

### 1.1 目标
- 移除敏捷面板任务卡片中的截止时间展示。
- 为敏捷面板任务卡片新增“指派至今”和“创建至今”两个时长字段。
- 为任务预览抽屉同步调整概要字段，保持与看板卡片口径一致。

### 1.2 已确认结论
- “指派至今”按当前负责人最后一次被指派的时间开始计算；负责人变更后重新计时。
- 调整范围包含敏捷面板任务卡片和任务预览抽屉，不扩散到其他任务列表页面。
- “创建至今”基于任务创建时间计算。
- 看板场景不能依赖逐任务查询变更日志，必须由主接口直接返回可用字段。

## 2. 范围与非目标

### 2.1 本次范围
- 后端任务数据模型补充负责人最新指派时间字段。
- 敏捷面板接口与任务详情接口返回时长相关字段。
- 敏捷面板卡片去掉截止时间，增加两个时长字段。
- 任务预览抽屉概要区去掉截止时间，增加指派时间与两个时长字段。
- 为新增字段写入必要单元测试与前端渲染测试。

### 2.2 非目标
- 不调整任务创建/编辑表单中的截止时间输入能力。
- 不修改除敏捷面板与该面板预览抽屉之外的任务展示页面。
- 不尝试通过历史日志还原历史任务的真实首次指派时间。

## 3. 现状摘要

### 3.1 当前前端展示
- 通用任务卡片 `TaskCard` 当前展示项目名、工时、负责人、截止时间。
- 敏捷面板卡片通过 `#taskCardAdapter.ts` 将 `AgileBoardTask` 映射为通用卡片结构。
- 任务预览抽屉概要区当前也展示负责人、工时、截止时间。

### 3.2 当前后端能力
- 任务详情 VO 已包含 `assignee`、`dueTime`、`createdAt`、`updatedAt`。
- 当前任务实体没有“负责人最近一次被指派时间”字段。
- 变更日志虽然记录了负责人字段变化，但展示值是昵称文本，不能稳定反推出当前负责人最近一次被指派时间。

### 3.3 当前痛点
- 截止时间不再符合当前敏捷面板的信息重点。
- “创建至今”虽然可由 `createdAt` 推导，但“指派至今”缺乏稳定数据来源。
- 如果前端逐任务查询变更日志，会引入看板 N+1 请求和口径分散问题。

## 4. 方案对比与最终选择

| 方案 | 做法 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- | --- |
| A | 给任务表增加 `assigneeAssignedAt`，接口直接返回时长字段 | 性能稳定、前后端口径统一、可复用 | 需要数据库迁移与写入逻辑 | 采用 |
| B | 后端只补 `assigneeAssignedAt`，前端自己算 `createdElapsedDays` | 接口改动略少 | 口径分散在两端，后续页面复用容易漂移 | 不采用 |
| C | 前端从变更日志反推指派时间 | 不改主接口 | 无法稳定识别当前负责人，且存在 N+1 请求 | 不采用 |

### 4.1 最终方案
- 数据库新增 `assigneeAssignedAt` 字段，作为当前负责人最近一次被指派的时间。
- 后端在任务创建、任务编辑时维护该字段。
- 后端在任务详情与看板列表响应中补充绝对时间字段与相对天数字段。
- 前端卡片和抽屉只负责展示，不在前端自行拼装时长口径。

## 5. 数据模型设计

### 5.1 数据库字段
- 表：`projectTask`
- 新增字段：`assigneeAssignedAt`
- 类型：`timestamp`
- 含义：当前负责人最近一次被指派到该任务的时间；若当前未分配负责人则为 `null`

### 5.2 后端响应字段

#### 任务详情与看板任务统一补充字段
- `assigneeAssignedAt?: string`
- `assigneeElapsedDays?: number`
- `createdElapsedDays: number`

### 5.3 字段含义
- `assigneeAssignedAt`
  - 当前负责人最近一次被指派时间。
  - 当前未分配负责人时返回 `null`。
- `assigneeElapsedDays`
  - 当前时间与 `assigneeAssignedAt` 的自然日差值，向下取整。
  - 当前未分配负责人时返回 `null`。
- `createdElapsedDays`
  - 当前时间与任务创建时间的自然日差值，向下取整。
  - 任务存在即有值，当天创建显示 `0`。

## 6. 后端写入与计算规则

### 6.1 创建任务
- 创建任务且传入负责人：
  - `assigneeAssignedAt = 当前时间`
- 创建任务未传负责人：
  - `assigneeAssignedAt = null`

### 6.2 编辑任务
- 负责人未变化：
  - 保持原 `assigneeAssignedAt` 不变
- 从未分配改为已分配：
  - `assigneeAssignedAt = 当前时间`
- 从负责人 A 改为负责人 B：
  - `assigneeAssignedAt = 当前时间`
- 从已分配改为未分配：
  - `assigneeAssignedAt = null`

### 6.3 天数计算规则
- 统一在后端计算，避免前端与后端因时区或格式化差异出现口径漂移。
- 计算公式按当前服务器时间与目标时间的自然日差值向下取整。
- 示例：
  - 同一天创建并查看，`createdElapsedDays = 0`
  - 指派后第 3 天查看，`assigneeElapsedDays = 3`

## 7. 历史数据迁移策略

### 7.1 回填规则
- 历史任务当前有负责人：
  - `assigneeAssignedAt = updateTime`
- 历史任务当前无负责人：
  - `assigneeAssignedAt = null`

### 7.2 选择该规则的原因
- 现有系统没有稳定的历史指派时间来源，无法准确还原真实历史首次指派时刻。
- 使用 `updateTime` 回填比统一使用 `createTime` 更接近当前负责人稳定存在的时间点。
- 该规则可以避免把很多中途才指派的老任务误算成超长滞留。

### 7.3 限制说明
- 历史任务的“指派至今”是回填口径，不代表真实历史首次指派时间。
- 该限制需要在交付说明中明确告知。

## 8. 前端展示设计

### 8.1 敏捷面板任务卡片
- 删除当前元信息中的“截止时间”。
- 保留现有项目名、工时、负责人。
- 新增两个元信息项：
  - `指派 X 天`
  - `创建 X 天`

### 8.2 卡片展示文案
- 已分配负责人：
  - `指派 3 天`
- 未分配负责人：
  - `指派 -`
- 创建时长：
  - `创建 8 天`

### 8.3 任务预览抽屉
- 概要区移除“截止时间”。
- 概要区新增：
  - `指派时间`
  - `指派至今`
  - `创建至今`

### 8.4 抽屉展示文案
- `指派时间：2026-04-08 10:23:00`
- `指派至今：3 天`
- `创建至今：8 天`
- 未分配负责人时：
  - `指派时间：-`
  - `指派至今：-`

### 8.5 展示设计原则
- 卡片是扫描视图，只保留短文案，避免增加视觉噪音。
- 抽屉是判断视图，同时给出绝对时间与相对时间，方便判断任务滞留原因。
- 本次替换掉截止时间，不额外增加卡片层级和复杂交互。

## 10. 测试与验证方案

### 10.1 后端测试
- 创建任务时：
  - 有负责人时写入 `assigneeAssignedAt`
  - 无负责人时保持 `null`
- 编辑任务时：
  - 负责人不变，字段不重置
  - 负责人从无到有，字段写当前时间
  - 负责人从 A 到 B，字段写当前时间
  - 负责人从有到无，字段清空
- 任务详情/看板接口返回新增字段且值正确
- 历史数据迁移后字段回填符合规则

### 10.2 前端测试
- `TaskCard` 渲染：
  - 不再显示截止时间
  - 正确显示 `指派 X 天`、`创建 X 天`
  - 未分配负责人时显示 `指派 -`
- 任务预览抽屉概要区：
  - 不再显示截止时间
  - 正确显示指派时间与两个时长字段

### 10.3 回归验证
- 看板加载、搜索、筛选、拖拽状态变更不受影响。
- 卡片点击预览、优先级切换行为不回归。
- 抽屉打开后概要区内容完整，字段顺序清晰。

## 11. 风险与控制策略

### 11.1 主要风险
- 历史数据回填值可能被误解为真实历史指派时间。
- 新增字段后，如果部分服务路径漏写，会导致“指派至今”停留在旧值。
- 前端若仍残留对 `dueTime` 的依赖，可能出现测试断言或展示回归。

### 11.2 控制策略
- 在迁移说明和交付说明中明确历史数据是回填口径。
- 在创建与编辑任务的服务层补充单元测试，覆盖负责人变化的全部分支。
- 前端统一通过卡片适配层与任务详情类型消费新字段，避免散落判断。

## 12. 验收标准

1. 敏捷面板卡片不再展示截止时间。
2. 卡片展示 `指派 X 天` 与 `创建 X 天`。
3. 未分配负责人时，卡片上的指派时长显示 `-`。
4. 任务预览抽屉概要区不再展示截止时间。
5. 任务预览抽屉展示 `指派时间`、`指派至今`、`创建至今`。
6. 创建任务和变更负责人后，`指派至今` 能按最新负责人重新开始计时。
7. 看板接口不引入逐任务追加查询，页面加载性能不出现明显退化。
